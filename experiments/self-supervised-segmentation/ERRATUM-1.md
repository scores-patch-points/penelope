# ERRATUM 1 to PREREG.md (544fcb4594e5f70f), written 2026-11-20 after the run
1. The edited books (Gutenberg) write the apostrophe as U+2019; the forms listed in the protocol and the code were the straight apostrophe only. So every apostrophe-form column on the EDITED side is "n/a" (fewer than five sentences carry the straight-apostrophe form), and P3/F3 could be evaluated only for the apostrophe-LESS variants. This is a protocol oversight, not a result. The criterion itself found the typographic "’s" with the largest gain on the edited side (+5484 bits) without being told.
2. The reference ordering (the codec session's preliminary smoke-run effects: n't +5.8, 'm +3.3, 've +2.9, 's +2.7, 're +1.9, 'd 0.0, 'll -1.0) was compared with the DESCRIPTION-LENGTH gain, as written. A comparison of the tagger-CONFIDENCE ordering with the same reference (Spearman 0.61, n = 7) was NOT pre-registered; it is reported as a post-hoc observation and carries no weight beyond that.
3. The run used a per-form, per-side cap of 200 sentences and 100 null draws; the cap was a run-time bound for time, declared in the script before any result and not in the protocol.
