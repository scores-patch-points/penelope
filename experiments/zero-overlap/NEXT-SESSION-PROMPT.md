## THE TASK
Build and test passage-level retrieval by REFERENT. The target is what a language model does well and cannot do verbatim: "where did a person talk about the captain?" must find the passage even if it never says "captain" ("the old man", "he", "the skipper"), AND return the exact words with a permanent address (byte span + sha256, re-openable, refusing drift). Verbatimness is the holograph (khora THE-HOLOGRAPH: every part carries a permanent address, the record re-expands it). An embedder may be used as ONE sense that nominates passages ("sniffing semantic similarity"); it is never the judge: a giver nominates, structure and usage license.
Suggested design (a proposal, not a decree; pre-register your own):
1. Independent gold from Wikipedia link markup: in a document's wikitext, a link [[Target|anchor]] says the anchor text refers to Target. Classify each gold mention by its anchor: SAME (anchor contains the target's name), PARTIAL (shares a token), DIFFERENT (no shared token: "the region" for Tuscany). Query = a referent (the target page/Q-id); gold passages = sentences containing its anchors. The links are GOLD only, never an input at run time.
2. Senses to compare, each reported alone and as a union: NAME string search; stem/prefix string search (a stronger mechanical baseline); a model-free recency chain (the sentence after a name mention that opens with a pronoun or a definite noun phrase); khora's own cast (names, pronoun binding, aliases; read through the one door); an embedder as one sense (needs an approved model download, see below). Metrics: recall@k and precision@k by mention type, and above all recall on the DIFFERENT stratum, where plain string matching cannot succeed. Every returned passage must re-open to its exact bytes (verify by re-slicing and sha256).
3. A never-read set chosen by member COUNT only, declared before fetching (do not read the leads before the single scoring), split label FRESH; everything else EXPLORATORY.
