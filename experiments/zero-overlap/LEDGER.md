# Zero-overlap sameness: capability ledger (2026-11-18)

Every row is a claim with its split label, its stamp and a command that reproduces it. A row is only as good as its label, and the label is CHECKED: `node gym/ledger-check.mjs` (and its test, part of `npm test`) reads this table and `splits.json` and fails when a row labels a number HELD-OUT or FRESH on a split an earlier row already scored, when a label does not match the roles in its Splits cell, when the Result text claims a label the row does not have, when a non-exploratory row has no stamp, or when a named script does not exist. Roles: held = a held-out scored once under frozen rules; fresh = a set read once under frozen rules; dev = used to build or tune; reused = a held-out already scored by an earlier row; explore = looked at, no claim. Row order is chronological. Negative results are rows. Data (Wikipedia leads, Gutenberg/Zenodotus texts, MRPC) is NOT committed; the fetch scripts regenerate it. Stamp = sha256 prefix of the pre-registration at filing; later addenda are appended in the same file.

## What the organs hold
`organs/frame-verdicts.mjs`, `organs/relation-fold.mjs` and `organs/vantage-verdicts.mjs` judge ladders, claims and folds GIVEN BY THE CALLER; the frames themselves (overlap, usage, numerals, area, ...) live in the scripts above, not in the organ. No organ here writes marks to a pharos log yet.

## Known limits
Fresh sets are small and fr/de only; held-out acts used by earlier frames were reused by later ones (disclosed per row); every extractor is regex; zero-overlap sameness with NO anchor at all (no number, no name, no area) is still unsolved: the fold returns "gap" there.
