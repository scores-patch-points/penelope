# PREREG-L1: a container reader from link structure, not from the word "region" (filed before it was run)
Why: PREREG-SOFTCHAIN found no eligible claimants in 16 new categories because the lead-sentence regex needs the word "region". The structure is in the infobox and the lead's links.
Reader L1 (declared, nothing learned, per language independently): the lead section's wikitext (section 0, including the infobox) of each article; its LINKS = the targets of [[Target]] / [[Target|label]], normalised (lower-case, underscores to spaces, anchors dropped), namespaced targets (File:, Category:, Image:, Template: and the like) and the article's own title removed. Within one scene (category) and one language, the document frequency df(t) = the number of scene members whose lead links t. A link is a CANDIDATE container if 2 <= df(t) <= floor(n / 2), n = the number of scene members with a fetched lead (links shared by every member are the country or boilerplate; links held by one member are unique things). The CONTAINER of a member = its candidate with the highest df; ties go to the link that appears first in its wikitext; none if no candidate. No word list, no threshold learned.
Data: F1-F5 pairs (fr and de); the other-language lead is the wikitext of the counterpart page found through English Wikipedia's own interlanguage links; everything fetched through the query API in batches.
Stage A (dev sanity, F1-F4): does L1 produce partitions that agree across languages at least as well as the regex containers did (destroy-set agreement vs the shuffle null, as in PREREG-HOLARCHY)? One erratum allowed; then FREEZE.
Stage B (confirmation, F5, run once): the soft chain of PREREG-SOFTCHAIN exactly (area within 0.10 first; region breaks ties among the area-agreeing; the areas from the frozen extractor; truth never used to build a set), with the L1 container replacing the regex container. Reported: eligible claimants, truth kept, mean answer-set size, unique-and-correct against area alone with Wilson 95% intervals, per language.
Falsifiers (in advance), on Stage B: (1) fewer than 30 eligible claimants in a language: too small; (2) truth kept < 0.90; (3) unique-and-correct not above area alone with non-overlapping intervals; (4) mean answer-set size not smaller than area alone. Stage A falsifier: L1 destroy-set agreement not above the shuffle null's 95th percentile in a language means L1 gives no cross-language structure.
Not claimed: that an L1 container is a REAL region (no gold for that here); only that it is a recurring-link grouping that agrees across languages.

## ADDENDUM-1 (user, mid-run: "these are about referents not strings"). Filed before any link was analysed.
A link target is a STRING; the container is a REFERENT. Two spellings or redirects of one place ("Tuscany", "Region of Tuscany") must be one container, and "Toscana" (it), "Toscane" (fr), "Toskana" (de) and "Tuscany" (en) are one referent. So L1 resolves every link target to a referent before anything is counted: the target is followed through its redirect and mapped to its Wikidata item (the Q-id, through the wiki's own pageprops wikibase_item). df(t), candidate selection and the container choice are then computed over REFERENTS (Q-ids), not strings; a link whose page has no Wikidata item stays a string-only referent, and the share of string-only referents is reported. The same rule applies to the claimant itself: a pair is identified by its referent (the Q-id of the English page).
Consequences: (a) the Stage A / Stage B tests are unchanged in form but the partition is over referents, so an English container and an other-language container can be compared DIRECTLY (same Q-id = same referent), in addition to the within-language partition agreement; I report both. (b) This does not use the Q-id of the pair's own article as evidence for the pair (identity of the pair is the gold, as before). (c) Wikidata is a giver: it nominates which strings are one referent; usage (the recurring-link structure beating a shuffle null) still licenses the container.
Also recorded as a standing correction for earlier frames: the region regex and the relations frame compared strings (names) within a language; aliases and redirects could split or merge containers. Their results are therefore lower bounds on what referent-level comparison would give, and the relations frame's "entities" were strings.

## ADDENDUM-2: the resolver, fixed before it was run (operational detail of ADDENDUM-1)
Resolver R (a giver, never evidence for a pair): for a language and a link target string, ask that language's own Wikipedia API (query, prop=pageprops, ppprop=wikibase_item, redirects=1, batches of 50) for the page's Wikidata item. REFERENT = the Q-id; if the page has no item or the target is a red link, the referent is a STRING-ONLY referent keyed "str:<lang>:<normalised target>". The share of string-only referents is reported. To bound the calls, only targets whose STRING document frequency within the scene and language is at least 2 are resolved (a referent whose spellings are each held by one member only is missed: a known limitation, reported).
Checks reported first, before any container is read (resolver validity, not a result about containers): (V1) for every true pair the Q-id of the English page equals the Q-id of the other-language page (pair identity by referent); (V2) the share of candidate links resolved to a Q-id.
Container (as ADDENDUM-1): over referents; df(referent) = scene members whose lead links it (any spelling); candidate if 2 <= df <= floor(n/2); container = highest df, ties to the earliest in the wikitext.
Cross-language comparisons use Q-ids only (P(English container Q-id = other-language container Q-id) among true pairs, and the destroy-set agreement of the within-language partitions against the same shuffle null as PREREG-HOLARCHY). Stage A on F1-F4; one erratum; freeze; Stage B on F5 once (the soft chain of PREREG-SOFTCHAIN with this container).
